# Preliminary email workspace

Apply `053_email_workspace.sql` after migrations 046–052 before opening **Email campaigns**. The workspace is an early, provider-free drafting area. It does not connect to MailerLite, sync subscribers, activate automations or send messages.

Staff with `email.edit` can create campaigns, create reusable text templates, add communications, copy template text into a communication and edit its subject, preview text, sender, audience description, trigger intent, relative days and message text. Audience is descriptive planning text, not a recipient selector. Relative timing is an unexecuted intent; it does not schedule a communication. Templates are copied into the communication, so later changes do not alter its saved text. This first version creates text templates but does not yet edit or delete them; it has no visual email builder, HTML rendering, provider status, campaign-level activation or delivery reports.

An editor can submit a complete communication for review. A user with `email.approve` may approve or request changes, including their own communication. Approvals use the exact revision and are invalidated only if that communication's content or configuration changes; unchanged saves preserve approval. The database stores prior revisions and actors. Email access is separate from event and social permissions. Board and Management receive View/Edit/Approve by default; General receives View/Edit; normal permission overrides and inactive-user denial apply. Existing staff can adjust overrides in Team. No provider-specific credentials or sends are introduced.

Campaigns, templates and communication lists use narrow selections and database pagination. Template application reads only the chosen template and communication on the server. Server actions and database functions independently enforce permissions and revisions; authenticated clients have no direct table-write grants. Drafts can be viewed by staff with `email.view`, so access should be assigned accordingly. Treat audience descriptions as non-sensitive: recipient lists and private contact information do not belong there.

Run `scripts/fixtures/email-workspace.sql` only against a fresh disposable PostgreSQL database using `psql -v ON_ERROR_STOP=1 -f scripts/fixtures/email-workspace.sql`. It checks default permissions, inactive users, denied direct writes, stale review, self-approval, unchanged content and independence of other communication approvals. It uses a synthetic profile/auth fixture. Test the full migration chain, role overrides, browser keyboard access, error and unsaved-edit behavior, and the eventual visual-builder choice before production use. No hosted migration or deployment has been performed.
