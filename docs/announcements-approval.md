# Announcement review and publication

Migrations `048_announcement_approval.sql` and `049_announcement_review_rpc.sql` introduce drafts, review, revision history and publication approval. Existing rows are grandfathered as approved: their public presentation, schedule, expiry, images and ordering are preserved, but no historical approver is invented. New announcements start as drafts. Saving a material change to a published or scheduled announcement withdraws it and returns it to draft; changing display order alone does not.

An editor submits a draft for review. A publisher can approve the displayed revision, request changes, or withdraw an approved announcement. A withdrawn announcement can be returned to draft and resubmitted. Approval requires a future expiration; publication and expiration continue to be evaluated on reads, without a scheduler. Changing the expiration of an expired announcement creates a draft for review. The change-history page shows previous states and content. Server actions use optimistic revision checks; review transitions use a permission-checked database function that requires the reviewed revision, and direct review-state updates are not granted. Material edits, state transitions and prior-revision history are recorded in one database transaction. This change does not add automatic event associations or external communications.

The public website reader in the sibling `wmcc-website` checkout does not yet explicitly filter `review_state = 'approved'`. This filter is necessary because staff RLS permits staff to see drafts in the CMS, including when they visit the public website with an authenticated session.
